# Telegram-бот AIVEXA — папки промптов и реферальная система

Бот выдаёт подписчикам бесплатные материалы (папки промптов, гайды, инструкции)
и ведёт реферальную программу: часть материалов открывается сразу, часть — за
приглашённых друзей.

Бот: **@aivexa_helper_bot** (токен проверен через `getMe` и сохранён в `admin_settings`).

---

## 1. Структура базы данных

### `prompt_folders` — материалы, которые выдаёт бот

| Поле | Тип | Назначение |
|------|-----|-----------|
| `title` | string | Название материала |
| `slug` | string | Технический идентификатор |
| `description` | string | Короткое описание под кнопкой |
| `icon` | string | Эмодзи на кнопке меню |
| `content_type` | dropdown | `prompts` / `guide` / `instruction` / `checklist` / `bonus` |
| `content` | longText | Текст сообщения, которое отправляет бот |
| `file` | file | Файл (PDF/ZIP), отправляется через `sendDocument` |
| `external_url` | string | Внешняя ссылка (Google Drive, Notion и т.п.) |
| `access_type` | dropdown | `free` — доступно сразу, `referral` — за приглашения |
| `required_referrals` | number | Сколько друзей нужно пригласить (для `referral`) |
| `order_position` | number | Порядок в меню |
| `active` | dropdown | `yes` / `no` |

### `telegram_users` — подписчики бота

| Поле | Тип | Назначение |
|------|-----|-----------|
| `telegram_id` | string | ID чата в Telegram (уникальный) |
| `username`, `first_name`, `last_name`, `language_code` | string | Профиль из Telegram |
| `referral_code` | string | Личный код (8 символов, без похожих букв) |
| `referrals_count` | number | Счётчик подтверждённых приглашений |
| `started_at`, `last_active_at` | string | Активность |
| `blocked` | dropdown | `yes`, если пользователь заблокировал бота |
| `user` | objectReference → `user` | Привязанный аккаунт на сайте |
| `invited_by` | objectReference → `telegram_users` | Кто пригласил |

### `telegram_deliveries` — журнал выдач

| Поле | Тип | Назначение |
|------|-----|-----------|
| `telegram_user` | objectReference → `telegram_users` | Кому выдали |
| `folder` | objectReference → `prompt_folders` | Что выдали |
| `delivered_at` | string | Когда |
| `delivery_reason` | dropdown | `welcome` / `request` / `referral_reward` |

### Настройки в `admin_settings`

`telegram_bot_token`, `telegram_bot_username`, `telegram_webhook_secret`,
`telegram_welcome_message`, `telegram_webhook_url`.

Токен хранится в базе, а не в `.env`, — владелец может перепривязать бота из
админ-панели в любой момент. Переменная `TELEGRAM_BOT_TOKEN` используется только
как запасной вариант, если в базе ничего нет.

## 2. Команды бота

| Команда | Действие |
|---------|----------|
| `/start` | Приветствие, регистрация подписчика, автовыдача всех бесплатных материалов |
| `/start <код>` | То же + засчитывает приглашение владельцу кода |
| `/start link<код>` | Привязывает Telegram к аккаунту на сайте |
| `/folders` | Список материалов с замками и прогрессом |
| `/ref` | Личная реферальная ссылка |
| `/stats` | Сколько приглашено и что уже открыто |
| `/link` | Инструкция по привязке аккаунта сайта |
| `/help` | Справка |

Меню продублировано инлайн-кнопками (`callback_query`): «Мои материалы»,
«Пригласить друга», «Моя статистика».

---

## 3. Логика реферальной системы

1. У каждого подписчика при первом `/start` создаётся `referral_code`.
   У зарегистрированного пользователя сайта код выдаётся при первом открытии
   `/referrals` (`GET /api/referral`).
2. Ссылка вида `https://t.me/aivexa_helper_bot?start=<код>`.
3. Приглашение засчитывается **один раз** и только:
   - если это первый `/start` приглашённого (повторный запуск счётчик не двигает);
   - если код не принадлежит самому приглашённому (самоприглашение игнорируется).
4. Код ищется сначала среди `telegram_users`, затем среди пользователей сайта —
   поэтому счётчики на сайте и в боте всегда совпадают.
5. Пригласившему приходит уведомление, `referrals_count` увеличивается, и все
   материалы, порог которых достигнут, отправляются автоматически с причиной
   `referral_reward`.

## 4. Админ-панель — `/admin/telegram`

- **Статус бота** — бейдж «Подключён / Не подключён», `@username`, счётчики
  подписчиков, приглашений, выдач и материалов.
- **Токен** — поле с маскировкой и кнопкой показа. Перед сохранением токен
  проверяется по формату и реальным запросом `getMe`; невалидный токен не
  записывается.
- **Приветственное сообщение** — редактируется без деплоя.
- **Webhook** — кнопки «Подключить» / «Отключить». При подключении генерируется
  секрет и передаётся в Telegram как `secret_token`; показываются `pending_updates`
  и последняя ошибка из `getWebhookInfo`. URL обязан быть HTTPS.
- **Материалы** — список с созданием/редактированием в модальном окне: эмодзи,
  тип, заголовок, описание, текст сообщения, ссылка, загрузка файла, правило
  доступа, число приглашений, порядок, активность.

Все запросы защищены проверкой роли администратора.

---

## 5. Страница пользователя — `/referrals`

Личная ссылка с копированием, кнопки «Открыть бота» и «Поделиться», кнопка
«Привязать мой Telegram» (deep-link `link<код>`), счётчики приглашений и
открытых материалов, сетка материалов с состоянием «открыто / нужно N друзей»
и блок «как это работает».

Страница привязана к аккаунту, поэтому она **не** входит в `publicRoutes`
middleware и не попадает в `sitemap.xml`.

---

## 6. Webhook

`POST /api/telegram/webhook`

- Проверяет заголовок `x-telegram-bot-api-secret-token`; при несовпадении — `403`.
- Всегда отвечает `200` после приёма (кроме `403`), чтобы Telegram не уходил в
  цикл повторов; все ошибки логируются в консоль.
- `GET` на тот же адрес — health-проба (показывает, подключён ли бот).

Адрес для подключения — **опубликованный** HTTPS-домен:
`https://aivexa.totalum-project.com/api/telegram/webhook`.
Временную preview-ссылку использовать нельзя: она меняется.

## 7. Начальные материалы

`scripts/seed-telegram.mjs` (идемпотентный) проверяет токен через `getMe`,
записывает 5 настроек и создаёт 6 материалов: 3 бесплатных и 3 реферальных
с порогами 1, 3 и 5 приглашений.

## 8. Что было починено (сентябрь 2026)

Бот не отвечал не из-за токена — токен валиден, `getMe` возвращает
`@aivexa_helper_bot`. Проблема была в том, что **webhook не был зарегистрирован**
в Telegram: `getWebhookInfo` возвращал пустой `url`, поэтому апдейты просто
никуда не уходили.

Сделано:

1. В `admin_settings` добавлен ключ `site_public_url` — публичный адрес сайта.
   Бот и генератор webhook-адреса берут домен **из него**, а не из
   `NEXT_PUBLIC_APP_URL`, чтобы ссылки в сообщениях никогда не указывали на
   временный preview-домен.
2. Поле «Публичный адрес сайта» добавлено в админку (`/admin/telegram`) и
   сохраняется вместе с остальными настройками.
3. Выполнен `setWebhook` на `https://aivexa.totalum-project.com/api/telegram/webhook`
   с `secret_token`; `getWebhookInfo` теперь возвращает этот адрес.
4. Через `setMyCommands` зарегистрированы команды `/start`, `/materials`,
   `/link`, `/stats` — роутер бота уже умел их обрабатывать.

**Важно:** webhook указывает на опубликованный домен. Бот начнёт отвечать
только после того, как вы нажмёте **Publish** в Totalum — до этого по адресу
`/api/telegram/webhook` живёт старая сборка, в которой этого маршрута ещё нет.

## 9. Кнопка бота в интерфейсе

Пропавшая интерактивная кнопка возвращена компонентом
`src/components/site/TelegramButton.tsx`:

- в шапке сайта (`variant="compact"`, скрыта на самых узких экранах);
- в мобильном меню (`variant="full"`);
- на главной странице отдельным блоком под секциями с призывом к действию.

Кнопка сама запрашивает `GET /api/telegram/bot` и **прячется**, если бот не
настроен, — так в интерфейсе никогда не появляется нерабочая ссылка.

## 10. Живой webhook и Mini App (сентябрь 2026)

### Почему бот молчал

`setWebhook` принимает **любой** HTTPS-адрес и не проверяет, что там кто-то
отвечает. Адрес был зарегистрирован на опубликованный домен, где до сих пор
живёт старая сборка без маршрута `/api/telegram/webhook`, поэтому
`getWebhookInfo` показывал:

```
"last_error_message": "Wrong response from the webhook: 404 Not Found"
```

Telegram бесконечно ретраил в 404 — снаружи это выглядит как полностью мёртвый
бот.

### Как это исправлено

1. **Проба перед регистрацией.** `probeWebhookEndpoint()` в `src/lib/telegram.ts`
   делает GET на `/api/telegram/webhook` и требует ответ `{ ok: true }`.
   `resolveWebhookBase()` перебирает кандидатов по приоритету — явный адрес,
   `site_public_url`, `NEXT_PUBLIC_APP_URL`, origin текущего запроса — и
   регистрирует **только тот, который реально отвечает**. Неотвечающий адрес
   больше зарегистрировать нельзя: админка вернёт понятную ошибку.
2. **`configureBot()`** одним вызовом настраивает всё: `setWebhook` с
   `secret_token`, `setMyCommands` и кнопку меню Mini App.
3. **Самолечение.** `maybeMigrateWebhook()` вызывается на каждом входящем
   апдейте (не чаще раза в 10 минут): если опубликованный домен начал отвечать,
   бот сам переносит webhook обратно на него. Никаких ручных действий после
   **Publish** не требуется.
4. **Скрипт** `scripts/setup-telegram-bot.mjs` делает то же самое из консоли:
   `node scripts/setup-telegram-bot.mjs [--base https://host]`.

### Надёжность команд и сообщений

- `parseCommand()` разбирает `/команда@имя_бота аргумент` — раньше в группах
  команды с суффиксом `@aivexa_helper_bot` игнорировались.
- Роутер обрабатывает `/start`, `/materials` (`/folders`), `/link` (`/ref`,
  `/invite`), `/stats`, `/help`, `/menu`; всё остальное открывает главное меню.
- `sendMessage()` режет тексты длиннее 3900 символов на несколько сообщений
  (клавиатура остаётся на последнем) и при ошибке разбора HTML повторяет отправку
  без `parse_mode` — сообщение доходит всегда.
- Приветственный текст из админки экранируется: символ `<` в нём больше не
  ломает отправку.

### Mini App

- Кнопка «🚀 Открыть AIVEXA» в главном меню бота — это `web_app`-кнопка, сайт
  открывается прямо внутри Telegram. Если публичный адрес не HTTPS, кнопка
  автоматически становится обычной ссылкой, чтобы Telegram не отклонил всё
  сообщение целиком.
- Синяя кнопка меню рядом с полем ввода настроена через `setChatMenuButton` на
  `https://aivexa.totalum-project.com/?tgmini=1`.
- `src/components/site/TelegramMiniApp.tsx` подключает
  `telegram-web-app.js`, вызывает `ready()` и `expand()`, задаёт цвета шапки и
  фона. Без `ready()` Telegram показывает вечный экран загрузки — именно так
  выглядит «Mini App с ошибкой». Вне Telegram компонент ничего не подключает.

### Что проверено

`/start`, `/materials`, `/link`, `/stats`, `/help`, `/stats@aivexa_helper_bot` и
`callback_query` прогнаны через реальный webhook-маршрут: все дают 200 и попадают
в нужный обработчик, апдейт с неверным секретом отклоняется с 403.
